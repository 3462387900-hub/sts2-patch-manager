# 尖塔修补站 · 管理器与模组修复工作台

Windows 原生 C# / WPF / .NET 9 工具，面向当前小队的杀戮尖塔 2 模组组合。

**[下载最新 Windows 版](https://github.com/3462387900-hub/sts2-patch-manager/releases/latest)** · [更新日志](更新日志.md) · [程序发布步骤](发布指南.md) · [如何上传补丁](补丁发布指南.md) · [鸣谢与来源](鸣谢与来源.md)

管理器源码与版本发布在本仓库。具体模组补丁及各自的适配说明继续保存在 [sts2-patches](https://github.com/3462387900-hub/sts2-patches)。管理器无需 GitHub 登录，不附带游戏或第三方模组本体。

## Beta 更新元数据访问优化（开发中）

- Beta 更新检查将优先读取与稳定版分离的 `manager-beta-update.json` 公开静态索引，避免频繁请求受匿名限流影响的 GitHub Releases API。
- 静态索引无法访问时才会回退官方 GitHub API；如果索引内容格式或 SHA-256 元数据不合法则直接拒绝，不静默信任其他版本。
- 初始索引来自已发布的 v0.14.4 Beta 1，仍与正式版 `manager-update.json` 隔离。旧版本尚未具备此改动，首次升级需要从 GitHub Release 手动获取测试版。
- 每次发布新的 Beta 时必须同步更新 Beta 静态索引；这一步需要纳入后续 Beta 发布流程，不得依赖普通用户提交任何 token。

## 0.11.8：修复自动更新包被安全校验拦截

修复部分旧版点击「下载并更新」后出现“更新包不能写入个人数据或游戏目录”并返回页面的问题。发布 ZIP 不再直接压缩构建测试目录，而是从经过 SHA256 校验的程序文件清单重建一个全新、干净的发布目录。测试/缓存/个人数据不会打包进新版本，安装器的文件写入限制不放宽。

## 0.11.7：GitHub MOD 更新检测与自动查找来源

「模组管理」→「普通 MOD」新增 GitHub 更新检查和自动查找来源。管理器先读取 MOD 的 `manifest.json` 中明确声明的 GitHub 地址；未声明时使用 MOD ID 搜索公开仓库，尝试核对仓库根目录的 `manifest.json`。搜索结果会作为候选显示，须由用户打开详情确认后关联，避免误认同名仓库。

已经关联的 MOD 可逐个或批量检查 GitHub 最新正式 Release，并在 MOD 列表显示版本状态。仓库关联按游戏目录保存在管理器数据区，不改写 MOD。仅检查公开 GitHub，不需要 Steam 下载权限，也不自动下载、安装或升级 MOD。无 Release、版本不规范、同名候选等情况会明确标为无法检测或需要人工核对。详见 [v0.11.7 发布说明](releases/v0.11.7.md)。

## 0.11.6：手动删除 MOD 后自动停用其独立修复补丁

管理器会记录每个游戏目录之前完整扫描时存在的 MOD。你在资源管理器中手动移走或删除某个 MOD，管理器检测到它确实消失且持续稳定后，会对关联的独立修复补丁进行校验：仅当所有目标 MOD 都已不存在、补丁属于本版审核指纹且原有安全依赖检查通过时，才自动停用并提示。**停用不删除文件，仍可重新启用。**

多目标修复不会因为少一个 MOD 就停用；未知补丁、被手动修改的补丁、游戏运行中或扫描不完整的场景仅提醒，不做自动操作。可在「模组管理 → 修复补丁」关闭该功能。详见 [v0.11.6 发布说明](releases/v0.11.6.md)。

## 0.10.2：独立修复补丁集中存放

- 在「模组管理」点击「整理独立补丁」，先预览受影响的完整文件夹，再确认移动到 `mods/_SpirePatch_Fixes/<原文件夹名>`。普通 MOD、共享目录、原 MOD 内置修复和无法核验版本的目录保持原位。
- 仅允许本版已审核且文件指纹匹配的独立补丁。游戏运行中、扫描不完整、有重复 ID、目标目录占用或文件变化时拒绝危险操作。
- 历史已安装批次的回滚日志记录了原文件路径：新版本会先保存原始备份记录，校验通过后同步更新受影响的回滚路径；未完成、损坏或无法识别的历史记录会阻止本次整理。
- 新的「选择安装」流程会优先将尚未安装的独立补丁放入专用文件夹；已存在的独立补丁继续使用实际清单所在目录。原 MOD 内置修复仍在原位执行。旧完整整合包流程保持原有目录行为。
- 每次整理将创建本地 JSON 操作记录；失败时尝试撤销已完成的移动。遇到文件占用、外部修改或进程异常可能需要根据记录人工恢复。
- 此功能仍需 Windows 实机和实际游戏加载验证，尤其是第三方 MOD 对嵌套目录的兼容性。建议先备份游戏 MOD 目录并退出游戏。

## 0.9：联机差异列表与一键处理

1. 双方更新至 0.9.0 或更新版本，选择各自游戏目录并导出清单。导出前会重新扫描。
2. 导入队友清单，与本机最新扫描比较；以这份清单为对齐目标，只调整本机。
3. 按列表查看「本机缺少」「本机多出」「本机已停用」「版本或文件不同」及具体原因。勾选项目，或使用「全选可处理项」。默认不勾选。
4. 退出游戏，点击「预览一键处理」。需要安装时先下载并校验已审核修复包，展示本次文件改动、必要关联和移出范围；此时尚未修改游戏文件。
5. 点击「确认一键处理」。缺失项备份安装，多出的**独立补丁**移到 `已停用模组_尖塔修补站`，匹配的已停用项直接恢复启用。
6. 处理后重新扫描并校验。移出但保留与队友完全缺失会显示「停用记录不同」，双方都未启用时无需重复处理。

队友清单是导出时快照。旧版清单可读，但没有可靠存在信息，不用于一键处理；队友后续有改动请重新导出。只比较本仓库已收录修复，不包含全部原 MOD、玩法配置或存档。

原 MOD 内置修复不能通过移走整个 MOD 来对齐；未知文件、缺少前置、共用目录、关联目标不一致等项目不可勾选，会说明原因。下载仍使用本版已审核的整合包，写入仅限所选及必要关联修复，不从导入清单提供的地址执行任意安装。

一次确认按步骤执行。失败时停止后续步骤，已完成项会明确列出，**不是整个批次自动撤销**。安装使用现有备份与最近批次回滚；移出项在模组管理中恢复。记录保存在管理器 `数据/联机对齐记录`，界面提供查看入口。

## 0.8.1：联机检查实时扫描修复

- “导出我的清单”在选择保存位置后重新扫描本机，写入实际扫描时间与当前状态。
- “导入队友清单”读取 JSON 后重新扫描本机再比对。删除、恢复或修改补丁后，无需先手动刷新。
- 页面保留差异结果，分别显示本机扫描时间和队友清单扫描时间。
- 读取失败不复用缓存；扫描不完整或有“需核对”项目时，明确显示不能确认一致。
- 队友清单是导出时的快照。双方都应更新至 0.8.1 或更新版本后重新导出；旧版清单仍可读取，但无法补查旧版导出时漏掉的文件变化。
- 范围仍为已收录补丁的扫描状态，不比较所有原 MOD 文件、配置及存档，不能单独证明完整联机兼容。

## 检查更新

- 左下角“检查更新”显示当前版本、正式新版本、发布日期和中文更新内容。
- 启动时后台检查一次，有新版只改变入口提示；不弹窗、不自动下载。
- 可以“下载并更新”“仅下载 ZIP”或“暂不更新”；下载支持进度和取消。
- 从本仓库 GitHub Releases 获取最新正式发布；使用数字版本比较，忽略测试版，不提示降级。
- 下载核对 GitHub 提供的 SHA256 和长度；损坏、超时或取消不会替换已有下载文件。
- 连接失败明确显示检查未完成，不会当作“已是最新版”。匿名访问可能受到 GitHub 限流，可重试或打开发布页。

0.7.1 优先读取本仓库 `manager-update.json` 的正式发布快照，减少匿名 GitHub API 限流影响；索引暂不可用时再尝试正式发布 API。下载优先走公开附件地址，并保留附件 API 备用。

选择“仅下载 ZIP”时仍由玩家完整解压运行。选择“下载并更新”且确认后，由外部助手等待当前窗口退出，再更新清单内的程序文件；新版启动后会返回启动确认，避免仅凭文件复制完成就认定更新可用。

0.6 及更早版本没有检查更新入口，首次需要手动下载当前新版；之后可以在管理器内查看后续发布。

## 0.6 新增：模组、启动、定位与返回

1. **自动定位游戏目录**：启动时恢复上次选择；没有有效记录时检查 Steam 库、正在运行的游戏位置和常用安装位置。只有一个候选时自动采用，多个候选时由你选择。左下角可随时自动查找或手动选择，不扫描整个硬盘。
2. **模组管理**：查看名称、ID、版本、作者和前置依赖，搜索和筛选启用/停用状态，查看详情或打开文件夹。停用/启用先预览，再明确确认。
3. **启动游戏**：顶部按钮启动当前目录的 `SlayTheSpire2.exe`，使用游戏目录作为工作目录；同一游戏已运行时不重复启动。安装、回滚或模组移动期间暂不可用。
4. **上一步**：顶部返回按钮恢复上一页的搜索条件和滚动位置。返回不会撤销文件操作或再次执行确认；切换游戏目录会清除旧扫描与操作预览。

四项功能和补丁安装共用左下角的当前游戏目录。自动定位失败时仍可手动选择。偏好记录保存在程序旁的 `数据\偏好.json`。

模组停用会把整个独立模组文件夹移动到游戏目录下的 `已停用模组_尖塔修补站`，保存原位置和文件校验记录；重新启用时恢复。不要删除或手动修改保留区。原位置被占用、停用内容发生变化时会拒绝恢复。这里的“启用”表示文件位于 `mods`；游戏内部另有开关时，以实际加载情况为准。

关闭游戏后才能移动模组。已声明的前置和管理器已知的补丁依赖会阻止危险启停；共享目录、嵌套目录、重复 ID、链接和不完整清单会保守阻止操作。未声明、未收录的依赖不能自动推断。停用的已知补丁显示为“已停用”，不会重新推荐安装，安装事务也会阻止向其重新写入。

本版管理本地已安装的模组，不提供创意工坊订阅、导入任意 ZIP 或删除模组。自动定位是有限范围查找，自定义安装位置仍可能需要手动选择。文件移动不会修改存档；进入存档仍需保留它所需的模组。

## 选择安装（沿用 0.5）

1. 在“安装与回滚”点击“选择要处理的补丁”，或从补丁详情点击“选择本项修复”。
2. 按真实扫描结果选择项目。待核对、不适用的项目不可选；已安装项目可用于补齐说明。
3. 必须的关联修复自动选中并单独标注；取消它的来源选择后会自动移除，不能拆开必要关联。
4. 点击“检查所选补丁方案”，查看本次实际修复、说明与旧补丁清理。
5. 确认后，只处理所选项目及必要关联项；已匹配的文件跳过。
6. “检查最近一次回滚”撤销整个最近批次，保留更早独立安装的补丁。继续回滚可撤销更早批次；暂不提供任意挑选历史批次或拆开关联修复回滚。

当前支持的选择范围是**本版已审核 v3 管理器载荷内的 17 项补丁**。下载仍使用完整 ZIP，安装只写所选文件；并非开放执行任意在线补丁配方。陌生草稿和未经审核的新包不会自动获得安装权限。

选择安装只要求选中补丁及关联项的真实前置条件。例如只安装超大回血显示修复时，不要求先安装第四幕。选择第四幕且已有联机兼容补丁时，必要的兼容更新会自动加入。

完整整合包入口继续保留。旧版独立 Chorale 补丁只有在选择其替代项 SpireTogetherFix 时才会纳入清理，未知旧版文件仍会阻止处理。

## 改动预览（沿用 0.4.1）

- 安装预览区分修复文件、说明与验证记录、旧补丁清理，按模组目录分组展示。
- 明确显示已匹配并跳过的文件；统计来自本次安装预检，而不是旧扫描结果。
- 只缺说明时显示“已有修复已匹配，仅需补齐说明”，确认按钮与完成提示同步调整。
- 已有说明发生变化时使用“更新说明”，避免把更新说成新增。
- 回滚预览区分“仅撤销说明改动”和实际修复回滚，不把补齐说明说成重装修复。
- 没有差异时不显示确认按钮。真实安装仍需独立预检与用户确认。

## 按 MOD 推荐补丁（沿用 0.4）

选择自己的游戏根目录后，根据每项补丁自带的 patch.json 检查实际文件，显示：

- **待修复**：现有游戏、原 MOD 与精确适配条件匹配；补丁缺失或属于已核对的旧文件。
- **需联动**：需要同时检查或更新关联补丁，详情可跳转查看关联项。
- **已安装**：补丁指纹、当前依赖及关联补丁条件匹配。只表示文件状态。
- **已停用**：通过本管理器停用并保留在停用区的已知补丁，不纳入重新安装。
- **不适用**：缺少受影响的 MOD 组合，或存在说明中排除的组合。
- **需核对**：未知版本、缺少运行前置、文件残缺、重复 ID、读取不完整、说明未经审核或关联条件未满足。

扫描不会安装补丁，也不根据 MOD 名称直接认定发生了故障。推荐是文件适配结论，不代表已经确认某个游戏问题，也不能证明完整联机正常。

## 使用

完整解压 Windows 版 ZIP，运行文件夹中的 `SpirePatch.exe`，不要只复制 exe。
先确认左下角自动定位的目录，或手动选择含 `SlayTheSpire2.exe` 的游戏目录；在在线补丁页点击“扫描游戏并推荐”。
总览可按状态查看数量，补丁库支持筛选与 MOD ID 搜索，详情显示推荐依据与关联修复。

在线源：https://github.com/3462387900-hub/sts2-patches

加载成功时按当前在线目录扫描；离线使用本版随附的 17 项说明快照。在线目录版本变化后需要重新扫描，避免把旧结果当成新版本结论。快照不是自动更新的独立补丁源。

## 安装与回滚

沿用备份与校验流程：选择目录 → 只读预检 → 查看改动 → 明确确认 → 备份、安装并校验。
**可选择已审核的补丁与必要关联项，或使用完整整合包。某个补丁适用，不代表完整整合包适用。**
安装页会独立核对本次选择的原文件、依赖与安装后适配条件；完整包入口仍检查整个包。后续修改文件、未知版本、损坏备份或变更过的预览会被拒绝。
回滚恢复安装前的真实状态，包含旧修复，不等于恢复所有 MOD 的官方原版。

下载缓存、操作日志在程序旁的 `数据` 文件夹；备份在自选游戏目录的 `mod_fix_backups`。升级时保留旧版的 `数据` 和游戏备份。新版本可重新选择同一已审核 ZIP 准备回滚。
游戏目录从不写死；取消目录选择不改变文件。此轮开发没有安装或回滚真实游戏目录。

## 适配数据与边界

- `patch-catalog.json` 保存从每项补丁自带说明提取的离线快照及 Git 提交号。
- `RecommendationScanner.cs` 只读识别清单 ID、定位改名文件夹、缓存 SHA256，并按“构建之间 OR / 构建条件 AND”匹配。
- `catalog-plan.json` 仅用于已审核整合包的旧文件白名单；只有完整说明与内置记录一致才可复用该白名单。
- 当前随包说明仍标为 draft；管理器为本版已审核整合包内的组件开放匹配与选择安装。陌生 draft 不因 DLL 相同就获得信任。
- 安装状态与未来关联更新分别计算。失去适配资格的补丁不能继续提供假定的未来文件指纹。
- 重复清单、无法读取的文件、链接目录、未知补丁残留都会保守处理。未收录的版本不猜测兼容。
- 扫描是某一时刻的文件快照；退出游戏后安装，安装前仍需重新预检。
- 报告格式升级为 schema 2，记录目录版本、匹配依据与关联项。旧报告需重新扫描导出。
- 联机比较仍只比较收录补丁的状态，不等于比较全体 MOD 或玩法配置。

## 开发

需 Windows 和 .NET SDK 9。发布文件夹已包含运行时。

配色参考 [Radix 的中性色与强调色搭配](https://www.radix-ui.com/colors/docs/palette-composition/composing-a-palette) 和 [shadcn 的语义配色](https://ui.shadcn.com/docs/theming)，按本工具定制：背景 `#F6F7F4`、侧栏 `#F0F2EC`、卡片 `#FFFFFF`、强调色 `#52735D`、正文 `#28352D`。界面仍使用原生 WPF。

PlanPresentation.cs 负责改动分类和文案，InstallerBridge.ps1 额外返回已核对的完整文件清单。分类只影响展示，不改变真实事务、备份、回滚或确认令牌。

## 选择安装的实现边界

SelectionPlanner.cs 使用本版内置说明计算必要关联，SelectionBridge.ps1 在实际事务锁内再次核对选择的组件、原文件白名单、适配构建与关联补丁。所有文件条件通过后才允许假定选中组件的预期文件；不会用未选择补丁的预期文件遮盖当前依赖不匹配。

确认令牌绑定选择范围、文件差异和实际依赖状态；更改选择或文件后需重新预览。未选择但已存在的受影响修复也会检查，避免悄悄破坏它们的依赖。备份记录只包含本批次实际改动，继续使用原有事务写入、失败恢复和回滚校验。

新版本不覆盖旧版程序或备份。请关闭旧窗口后使用项目里的启动快捷方式进入新版。没有在真实游戏目录安装或回滚本轮测试；所有写入验证都在带标记的隔离目录进行。
