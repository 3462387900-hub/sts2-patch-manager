# 尖塔修补站 v0.13.0 · 创意工坊下载、批量管理与环境恢复

本版把此前分阶段开发的模组来源下载、批量更新、依赖分析和环境保护整合到一个正式版本，同时完善 MOD 卡片交互，并增加管理器自身旧更新文件的安全清理。

## 主要更新

### 尖塔补给站下载与安装

- 在维护者授权下接入 [尖塔补给站](https://workshop.apricityx.top/) 的下载接口。
- 支持输入 Workshop ID，以及 Steam 创意工坊和尖塔补给站分享链接。
- 获取 UGC Manifest 与 Chunk，执行 AES 解密、压缩解码、文件重组和完整性校验。
- 下载完成后先展示 MOD 身份、版本、文件和目标目录，再由用户确认安装。
- 新 MOD 安装到独立目录；同 ID 更新前备份旧版本，替换失败时尝试回滚。
- 按游戏目录和 MOD ID 保存 Workshop 来源关联，详情页可重新获取、更新或解除关联。
- 更新检测读取只读 Manifest 标识并与本地基线比较；检测到变化后仍需完整下载、校验、预览和人工确认。

### 本地 ZIP 导入

- 增加「导入本地 ZIP」入口，支持导入用户已下载的单个 MOD。
- 导入前检查压缩包大小、文件数量、路径穿越、链接、Windows 保留名称、可执行脚本、压缩比例、MOD 清单及必需 DLL/PCK。
- 只允许一个有效 MOD 清单，不允许混合多个 MOD、重复 ID 或覆盖现有目录。
- 导入前展示 MOD ID、文件数量、解压大小、前置声明和目标路径；用户确认后才写入。
- 导入前自动创建完整 MOD 环境保护快照。

本地 ZIP 来自浏览器或第三方网站时，不代表 Steam 官方身份认证；请自行核对来源与兼容性。

### 批量创意工坊更新

- 可对已确认 Workshop 来源的普通 MOD 批量检查更新。
- 仅处理已启用且确实检测到更新的 MOD；停用项、修复补丁、未绑定来源或状态不确定的项目会跳过。
- 每个 MOD 单独重新下载、校验并核对 MOD ID，逐项显示旧/新版本、文件数、大小及目标目录。
- 每项均可选择更新、跳过或停止后续任务；失败后停止后续项目，已完成的项目保持不变。
- 每次实际写入前自动创建完整环境保护快照，并继续使用单 MOD 备份、原子替换和回滚机制。

### MOD 依赖关系分析

- 新增依赖关系图，显示前置模组到依赖者的方向。
- 检查缺失前置、已停用前置、重复 ID、版本范围不匹配、未知版本、无效版本约束和依赖循环。
- 同时识别启用区和管理器停用保留区中的 MOD。
- MOD 卡片与详情页显示依赖摘要、前置列表和依赖者列表。
- 分析为只读，不会自动安装、启用、停用、移动或删除 MOD。

依赖图只根据 MOD 清单及已知修复补丁声明分析；未声明的运行时依赖和加载顺序要求无法自动推断。

### 完整 MOD 环境快照与恢复

- 快照包含当前游戏目录的 `mods` 和「已停用模组_尖塔修补站」保留区，保留文件内容、空目录、时间戳、大小及 SHA-256。
- 快照列表支持手动创建、按时间查看、恢复前差异预览和单份删除。
- 恢复前重新核对预览令牌，防止预览后文件变化仍覆盖当前环境。
- 恢复前自动保存当前环境；暂存目录校验通过后才替换两个 MOD 目录，并校验恢复结果。
- 记录目录交换事务状态；管理器下次扫描时会检查未完成的恢复事务，尝试将原目录恢复，并提示自动恢复结果。
- GitHub、创意工坊更新和本地 ZIP 导入在实际写入前自动创建保护快照。

**快照边界：** 不包含游戏本体、存档、日志、管理器设置、GitHub / Workshop 来源绑定和每个 MOD 独立的历史版本备份。每份快照最多 50,000 个文件、30 GB；快照为完整副本，会占用额外磁盘空间。恢复前请退出游戏。

### MOD 卡片交互优化

- 勾选框与卡片按钮采用统一的柔和毛玻璃样式，扩大勾选操作区域。
- 卡片边框保持固定 1px，不再因选中而改变布局。
- 鼠标悬停和选中状态采用更柔和的底色与描边。
- 选择单张卡片时不再遍历并重建所有可见卡片，保留虚拟化控件实例，改善列表操作流畅度。

### 管理器旧版本文件清理

- 「检查更新」页面新增「清理旧版本文件」。
- 只识别管理器自己的历史更新任务和指定命名格式的旧版 ZIP。
- 仅清理已完成、已确认成功重启、超过 24 小时且目录内容完全符合预期的旧任务。
- 始终保留最近一次成功更新的完整回滚任务；失败、未完成、无法确认归属、带链接或含用户文件的目录会保守保留。
- 清理前显示预计释放空间并要求确认；执行前重新扫描，文件状态变化则拒绝删除。
- 正常启动后会在等待一段时间并确认管理器空闲后尝试清理；启动清理失败不会阻止管理器运行。

## 验证边界与已知限制

- Manifest 签名验证尚未实现；管理器不会宣称签名已通过验证。
- 本机游戏分支与远端 Manifest 的匹配验证尚未实现；安装预览会明确提示这一限制。
- 本地 ZIP 是不可信输入，导入功能不证明文件来自 Steam。
- 依赖分析只覆盖清单及管理器已知声明，不覆盖未声明的运行时依赖或加载顺序。
- 环境快照恢复应在游戏退出后执行；快照不包含存档，恢复后的 MOD 组合仍需与存档兼容。
- 自动化构建与隔离测试不能替代所有真实 MOD、游戏版本、多人联机和长时间运行场景的实机验证。

## 更新方式

下载 Windows x64 版本，解压到独立的普通文件夹后运行 `SpirePatch.exe`。从 v0.12.4 升级时保留原管理器的「数据」文件夹，以继续使用已有设置、GitHub 仓库关联、Workshop 来源关联和版本基线。

不要将管理器解压到游戏目录，也不要只复制 EXE 文件。
