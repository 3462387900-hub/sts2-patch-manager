# 尖塔修补站 v0.12.4 · MOD 卡片管理与批量操作

本次将原本的 MOD 长条列表改为可勾选的信息卡片，并完善批量操作的执行预览与结果反馈。更新仍保留原有独立修复补丁和安全文件操作逻辑。

## 模组管理
- 使用 1–3 列响应式卡片：卡片名称字体放大，模组 ID、版本号、作者、更新状态、依赖情况均有明确标签；窄窗口自动减少列数。
- 卡片左上角加入独立勾选框，直接提供启停、检查更新/来源关联入口和更多操作；点击模组名称可查看完整详情。
- 新增「有更新」「有问题」筛选；筛选或搜索不会悄悄清除已选择的模组，工具栏明确标出被隐藏的选择项。
- 移除重复的顶部批量 GitHub 来源入口，将批量动作统一放到选中卡片后出现的工具栏中。

## 批量操作与安全
- 批量查找 GitHub 来源每轮最多处理 8 项，跳过已绑定或已有缓存的来源；只产生候选，仍需用户手动核验后关联。
- 批量 GitHub 更新检测仅读取已绑定仓库的最新正式 Release；不会下载或修改模组。
- 批量启停先展示选中清单、可处理项、依赖待复核项与跳过原因；执行时逐项复核文件、模组 ID、依赖和运行环境，通过原有预览与应用机制处理。
- 批量过程显示当前项目、完成进度和逐项结果；用户可停止尚未开始的后续任务，已成功操作不会在未确认的情况下自动回滚。
- 保留 GitHub 下载更新的 SHA-256 校验、旧版本备份与恢复、孤立补丁自动停用、修复补丁健康以及联机检查。

## 验证与边界
- 使用 Windows CI 运行 Release 构建、隔离自测、WPF 交互回归与发布包运行数据排除验证。
- 回归覆盖卡片全选与取消、筛选下隐藏选择提示、批量预览取消及窄窗口动作可见性。
- 自动化验证不能替代所有真实 MOD、系统缩放或多人联机场景；复杂 MOD 依赖仍以执行时的安全检查为准。
